# LowRegret V0.4：个性化决策闭环

## 版本与边界

- 应用：`0.4.0`
- 客观风险：`risk-v0.3`
- 用户画像：`taste-v0.1`
- 推荐排序：`recommendation-v0.4`
- 深挖风险：`deep-risk-v0.1`

Risk 只回答餐厅客观上是否容易踩坑；Taste、行为和近期饮食历史只影响排序，不得进入 RiskScore。V0.4 不增加数据源、机器学习、Redis、消息队列或登录体系。

## 数据流

```text
高德 POI → 餐饮身份与硬过滤 → 百度 Evidence → risk-v0.3
                                                   ↓
匿名用户 → TasteProfile + 近期饮食历史 → LowRegretScore v0.4
                                                   ↓
                            高风险剔除 → 有限探索 → 6 家冻结候选池
                                                   ↓
                    ACCEPT / REROLL / NAVIGATE / SKIP / 三态反馈
                                                   ↓
                              taste-v0.1 与 user_food_history
```

## TasteProfile v0.1

画像持久化在 `user_taste_profile`，包含细品类、价格档、距离档、五种口味权重和隐式累加器，单项限制在 `[-3,3]`。读取时按 90 天半衰期衰减。显式反馈增量为 LIKE `+1`、NORMAL `+0.1`、DISLIKE `-1`；口味只更新用户本次实际选择的标签。

画像可信度为 `min(1, (显式反馈数 + floor(隐式行为数/3)) / 5)`。最终偏好向 50 分收缩，因此新用户保持中性，少量行为不会造成过度个性化。旧 schemaVersion=2 画像由 V6 迁入正式表；旧表继续只读。

餐厅公共口味必须由至少两个不同匿名用户标注。当前用户自己标注过的餐厅可立即使用其标签；候选口味按批次加载，缺失时为中性。

## 行为与近期历史

客户端可提交 ACCEPT、NAVIGATE、SKIP；RECOMMENDED、REROLL 由服务端随主事务记录。事件通过 `eventId` 幂等。ACCEPT/NAVIGATE 各 `+0.1`，同会话同餐厅最多 `+0.2`；REROLL `-0.1`，SKIP `-0.05`。同一特征积累 3 个事件后才更新长期画像，单批限制在 `[-0.25,+0.25]`。

只有 LIKE/NORMAL/DISLIKE 写入 `user_food_history`。排序只应用最强一项近期惩罚：7 天同店 DISLIKE `-40`、同店其他反馈 `-30`、连续两个自然日同品类 `-12`、最近一个自然日同品类 `-5`。自然日使用 Asia/Shanghai，候选只降权不删除。

## LowRegretScore v0.4

```text
WeightedScore =
  25% RestaurantQuality + 25% RiskSafety + 20% TasteMatch
+ 12% BudgetFit + 10% DistanceFit + 8% RecentDiversity

LowRegretScore = clamp(WeightedScore - strongestRecentPenalty
                       + ExplorationBonus, 0, 100)
```

80% 使用个性化选择，20% 尝试低风险新类型。探索候选必须为 LOW、Risk confidence 不低于 0.6、7 天没吃过同品类，且不存在明确负偏好或 30 天该品类 DISLIKE；没有合格候选时自动回退。探索最高只加 5 分。

## API 与数据库

- `RecommendationResponse.personalization` 返回 Taste 分、可信度、选择模式、理由和算法版本。
- 反馈请求可增加最多 3 个 `flavorTags`；同会话同餐厅只接受一次反馈。
- 新增 `POST /api/v1/recommendations/{id}/behaviors`，客户端只提交 ACCEPT/NAVIGATE/SKIP。
- Flyway V6 新增 `user_taste_profile`、`user_behavior`、`user_food_history`、`restaurant_flavor_observation`，并为推荐候选保存完整个性化快照。
- `v_risk_calibration` 按风险桶统计 DISLIKE 率；`v_recommendation_metrics` 按日期、算法版本和选择模式统计接受、导航、reroll 与 DISLIKE 指标。

当前推荐会话冻结后，后续反馈不会重排其 reroll 候选；只影响下一次新推荐。
