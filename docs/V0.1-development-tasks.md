# ELMA 今天吃什么 V0.1 开发任务

## 1. 当前基线

- 仓库当前只有产品介绍与 V0.1 技术/产品方案，无 README、后端或前端工程。
- Git 尚无首次提交；两份既有方案文件已在暂存区，开发时不得覆盖或重写。
- 技术边界已确定：uni-app + Vue 3 + TypeScript、Java 17 + Spring Boot、PostgreSQL、高德 Web Service。
- V0.1 只验证“定位 → 条件 → 推荐 → 换一家 → 导航 → 反馈”的完整闭环。

## 2. 契约决策

接口事实源为 [`contracts/openapi.yaml`](../contracts/openapi.yaml)。前后端实现不得自行添加另一套字段含义。

### 2.1 推荐会话

- `POST /api/v1/recommendations` 创建推荐会话，只返回一家餐厅。
- 客户端首次启动生成匿名 UUID，并在三个接口中使用 `X-Anonymous-User-Id` 请求头。
- 经纬度统一使用 GCJ-02，避免高德 POI 与导航出现坐标偏移。
- `radius` 只允许 500/1000/2000/3000 米；`maxBudget=null` 表示不限。

### 2.2 换一家

- 服务端在首次推荐时固定最多 3 个优质候选 A/B/C，并保存展示游标。
- 前两次 reroll 依次展示 B/C；耗尽后不再生成新候选，只返回初始 A。
- 客户端在 `alternativesRemaining=0` 后不再展示“换一家”按钮。

### 2.3 反馈

- 反馈请求按现有产品方案只携带 `result`，服务端将反馈关联到该会话当前展示的餐厅。
- V0.1 每次提交创建一条反馈记录；前端在提交期间禁用重复点击。
- V0.1 只记录 `LIKE/NORMAL/DISLIKE`，不即时训练或修改推荐结果。

## 4. V0.1 明确不做

不做登录、画像训练、评论抓取、多平台证据、支付/团购/外卖、排行榜、社交、Redis、消息队列、微服务、Python/AI Runtime。前端不包含 RiskEngine、Low Regret 排序、高德 Web Service Key 或 POI 直连逻辑。

## 5. Demo 验收门槛

1. 用户允许定位后能提交条件；拒绝定位时有可理解的提示且不申请后台定位。
2. 服务端返回真实 POI 中的一家推荐，每个候选都有可解释风险结果和算法版本。
3. 用户最多看到 A/B/C 三家，前端不会形成无限刷新列表。
4. 点击“就它了”能打开地图位置；反馈可追踪到推荐会话和具体餐厅。
5. 高德 Key 只存在于后端运行环境，前端产物和仓库均不包含敏感 Key。
