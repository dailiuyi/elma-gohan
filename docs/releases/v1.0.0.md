# ELMA 今天吃什么 v1.0.0

发布日期：2026-08-28

这是 ELMA 今天吃什么的首个正式版本。产品仍坚持“不是再给一张列表，而是给一个认真筛过的选择”：附近餐厅先经过结构化数据核验和客观风险过滤，再结合当前预算、距离、匿名偏好与近期饮食历史，最终只推荐一家。

## 正式版能力

- 高德作为主餐厅来源，百度作为第二结构化 Evidence；平台失败时可降级，不拖垮主推荐。
- `risk-v0.3.1` 只表达餐厅的客观踩坑风险，用户口味不会污染 RiskScore。
- `taste-v0.1` 从 LIKE / NORMAL / DISLIKE、轻量行为和近期历史形成可解释画像。
- `recommendation-v0.4.1` 组合质量、风险、口味、预算、距离和近期多样性，并保留受约束的低风险探索。
- 每个会话冻结最多 6 家不同候选，首次推荐后最多换 5 次，不会随机放回高风险候选。
- 用户主动点击“深挖一下”时，才查询公开 Web Search 线索；结果不参与主排序。
- 首页提供隐私说明和数据删除入口，可删除当前匿名身份关联的全部推荐与个性化数据。

## 兼容性与数据

- 应用版本：`1.0.0`
- 风险算法：`risk-v0.3.1`
- 画像算法：`taste-v0.1`
- 推荐算法：`recommendation-v0.4.1`
- 数据库迁移：Flyway `V1` 至 `V8`
- 客户端：uni-app Vue 3 / TypeScript，支持微信小程序与 H5 构建。

## 升级说明

后端从旧版升级时由 Flyway 自动执行尚未应用的增量迁移。真实密钥仍必须只通过服务器环境变量提供；不要把高德、百度、Brave 或数据库凭据写入仓库、前端代码或构建产物。

用户数据删除接口为 `DELETE /api/v1/users/me/data`，以 `X-Anonymous-User-Id` 标识删除范围。该操作不删除共享餐厅和地图 Evidence。

## 已知边界

- 当前仍使用匿名 UUID，不提供登录或跨设备画像同步。
- 推荐规则尚未使用机器学习，Risk 校准需要继续积累真实反馈样本。
- Brave 深挖依赖公开搜索索引，结果较少时会明确显示没有找到同店公开线索。
- 外部地图 API 的配额、字段缺失和覆盖范围仍可能影响候选完整度；系统会尽量降级并给出提示。
