一次只推荐一家餐厅，并说明推荐依据。

ELMA 是一个单结果餐厅推荐系统。它会处理真实 POI、信息缺失、口味反馈较少和风险判断不确定等情况，再根据质量、安全、口味、距离和预算选择一家餐厅。每次推荐都会保留决策数据，便于解释、重放和比较算法版本。

03 / Algorithm Versions

v0.4.1 与 v0.5 的关系

线上结果目前由 v0.4.1 生成。系统会在响应提交以后异步计算 v0.5 Shadow。Shadow 任务失败时不会回滚原有请求。v0.5 需要完成离线重放、指标门禁和小流量灰度以后，才会考虑参与线上响应。

05 / Engineering Implementation

算法进入生产系统后的工程处理

我在项目中同时处理了接口边界、数据保存、失败隔离和发布控制。当前线上响应保持不变，新算法可以独立比较，每次决策可以重放，运营页面只读取聚合数据。

Shadow 不改变原有响应

系统在主事务提交以后触发异步计算。查重和保存分别使用短事务，任务失败、超时或者队列拒绝都不会回滚 v0.4.1 的响应。

保存重放所需的数据

V9 快照会保存候选、分项、排序、选择概率、随机种子、选择原因和配置哈希，为离线比较和审计提供数据。

06 / Current Limits

当前限制

1
正式流量尚未独立计量下一步需要增加 client_channel。现阶段不能把 64 个匿名标识称为真实用户。
2
反馈样本仍然较少当前数据只能用于描述行为基线，不能用于宣称 v0.5 已经提升接受率。
3
v0.5 尚未参与线上响应项目需要先完成离线重放、分层诊断和指标门禁，再单独评审灰度方案。
