# ELMA 产品与算法 Demo 交接

## 目标

把 ELMA 从“数据库运营看板”推进为可用于产品介绍、项目答辩和求职面试的交互式案例。Demo 需要讲清楚产品问题、一次推荐如何产生、算法怎样演进、数据如何验证，以及当前仍有哪些限制。

## 目录边界

- `index.html`：公开展示方向的单文件 Demo，可直接离线打开。
- `open-demo.cmd`：Windows 下一键用默认浏览器打开 Demo。
- 本目录不连接数据库、不调用后端、不包含刷新生产数据的能力。
- 现有 `output/database-guide/` 继续作为私人只读运营看板，不在本 Demo 中复制连接信息或生产数据明细。
- 不修改客户端 API 契约，不启用 SafeRegret v0.5 serving，不部署公网。

## 事实口径

- 当前线上决策：`recommendation-v0.4.1`，包含硬过滤、风险评估、TasteProfile 个性化、LowRegret 排序、有限探索和冻结候选池。
- 当前影子算法：`risk-v0.5` + `recommendation-v0.5`，只执行 Shadow 计算，不改变线上响应。
- V9 决策快照用于保存 served/shadow 候选、排名、得分、选择原因、随机种子和配置哈希，支持重放与审计。
- 最新已读取的 30 天本地只读快照时间为 `2026-09-04 10:32`。包含 298 个推荐会话、515 家餐厅、90 个 Shadow 快照；这些数据可能包含内部调试流量。
- 64 个活跃匿名标识不等于 64 名真实用户。
- Shadow 覆盖率 30.2% 只表示快照落盘覆盖。
- 55/90（61.1%）表示新旧算法首选不同，不表示 v0.5 提升 61.1%。
- 当前 Shadow 样本中 `noSelectable = 0`，只描述这 90 个快照。

## 页面叙事

1. 产品命题：不再给用户十个选项，而是在不完整 Evidence 下直接推荐一家更不容易后悔的餐厅。
2. 决策流水线：条件输入、真实 POI、身份校验、硬过滤、风险、个性化、排序、候选冻结、反馈闭环。
3. 单次推荐解释：用明确标记的演示候选展示质量、风险、口味、距离、预算和近期重复惩罚。
4. 算法演进：规则与基础 LowRegret → Evidence 与 TasteProfile → v0.4.1 个性化探索 → v0.5 Shadow。
5. 量化证据：展示运行规模、产品基线和 Shadow 诊断，并为每个指标标注边界。
6. 工程保障：事务外 Shadow、有界执行、决策快照、只读聚合、失败不影响旧响应。
7. 当前限制：调试流量尚未分离、反馈样本稀疏、v0.5 尚未正式灰度。

## 交互范围

- 点击决策流水线步骤可查看该阶段的输入、动作和输出。
- 切换候选可查看不同的分项得分与推荐结论。
- 切换算法版本可比较 v0.4.1 serving 与 v0.5 shadow 的定位。
- 指标卡提供口径说明，避免把规模、分歧和业务提升混淆。

## 验证与验收

- 自动检查：单文件离线、无外部请求、无生产连接信息、关键文案和交互状态正确。
- 视觉检查：按照根目录 `AGENTS.md`，默认由用户人工验收；除非用户明确声明长任务或 Goal 模式，不主动截图或进行自动视觉审查。
- 人工验收入口：双击 `output/product-demo/open-demo.cmd`，或直接打开 `output/product-demo/index.html`。
